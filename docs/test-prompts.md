# 待测用例 · 可直接粘贴的提示词

对应 `docs/test-plan.md` 里挑出的四条高风险/未覆盖用例。每条给出**前置准备**、
**可直接粘贴的提示词**、**通过标准**和**快速核对命令**。

统一约定：`dsh` 会话的工作区＝你执行命令时所在的目录；建议每条用例开一个
**干净的空目录**，避免上一条的产物干扰。

## E4 · 模型会不会用 `sjs_worktree`

**为什么测**：两次完整 E2E 里模型一次都没调用过它。要么是 SKILL 引导不到位，
要么这功能对模型没价值——直接决定阶段 1 这部分该不该留。

**前置**：先备一份"已定稿"的工作簿。

```powershell
mkdir D:\sjs-e2e\t4-worktree; cd D:\sjs-e2e\t4-worktree
dsh --profile sjs "建一个工资表 工资表2026-05.ssjson：列 序号/姓名/部门/基本工资/绩效工资/社保扣款/实发工资，录入 10 人，实发用公式 =D+E-F，末行合计。"
```

记下原文件指纹，后面要用：

```powershell
Get-FileHash .\工资表2026-05.ssjson -Algorithm SHA256
```
569E5BB2A87419B6CC3F781B5C9BF785E64F074FA9BF9BAB89371801C13FCE09

**提示词（主用例）**

> 工作区里有一份已定稿的 `工资表2026-05.ssjson`。我想试试把绩效工资整体上调 10%
> 的效果，但**不要动原文件**——先给我一份隔离的草稿看看，我确认没问题再决定要不要
> 合到正式的上面。做完告诉我：草稿文件和原文件分别叫什么、原文件有没有被改过。

**通过标准**
- [ ] 调用了 `sjs_worktree`（`action: "create"`），而不是直接改原文件
- [ ] 后续编辑作用在 `.spreadjs/drafts/` 下的草稿路径上
- [ ] 原文件 SHA256 **与前置记录一致**（没被动过）
- [ ] 模型能说清"草稿 vs 正式"两个文件分别是什么

**核对**

```powershell
Get-FileHash .\工资表2026-05.ssjson -Algorithm SHA256   # 应和前置一致
Get-ChildItem .spreadjs\drafts -Recurse                # 应有草稿
```

**提示词（补充：探测它是否"知道"这工具）**

> 我想对 `工资表2026-05.ssjson` 做几处改动，但怕改坏原文件。**先别动手**，告诉我
> 有哪几种做法能让我在不影响原文件的前提下试改？各自适合什么场景？

**通过标准**：能主动说出 worktree/草稿快照机制（而不是只会说"我先复制一份文件"）。
若只会复制文件 → SKILL 对 worktree 的引导需要加强。

## A6 · 真实 Excel 特性往返保真

**为什么测**：真实 Excel 文件的高频特性（条件格式、数据验证、批注、图片、定义名称）
在往返中是否保留，完全没测过。

### Leg 1 · 自产自销（先建立基线，无需 Excel）

**前置**：空目录。

```powershell
mkdir D:\sjs-e2e\t6-features; cd D:\sjs-e2e\t6-features
```

**提示词**

> 用 sjs 工具建一个工作簿，尽量覆盖这些 Excel 特性（能做的都做上）：
> ① 条件格式——销售额小于 100 的单元格标红
> ② 数据验证——某一列只允许 1–100 的整数
> ③ 单元格批注——给表头加一条说明
> ④ 插入一张小图片
> ⑤ 定义名称——把 B2:B10 命名为 `销售额`
> ⑥ 合并单元格 + 边框 + 数字千分位格式
>
> 做完导出 `特性往返.xlsx`，然后**重新导入**这个 xlsx 得到一份新的 ssjson，
> 逐项核对上面 6 项是否都还在。按 ①②③④⑤⑥ 逐条列出"保留 / 丢失 / 说不清"，
> 丢失的要说明你是怎么判断的。

**通过标准**
- [ ] 6 项都有明确结论，且给出判断依据（不是"看起来还在"）
- [ ] 导出 + 再导入后，原工作簿文件未被破坏
- [ ] 丢项被如实报告（**不允许**把丢失说成保留）

### Leg 2 · 真实 Excel/WPS 介入（需要装 Excel 或 WPS）

**前置**：用 Excel 打开 Leg 1 产出的 `特性往返.xlsx` → **另存为**
`特性往返_fromExcel.xlsx`（WPS 再另存一份）；把文件放到工作区 `data\` 下。

**提示词**

> 导入 `data/特性往返_fromExcel.xlsx`，逐项核对这 6 个特性是否保留：
> ①条件格式 ②数据验证 ③批注 ④图片 ⑤定义名称 ⑥合并单元格。
> 哪一项丢了就明确说出来，不要含糊，也不要为了好看而说"都保留了"。

**通过标准**
- [ ] 逐项结论 + 依据
- [ ] 中文不乱码、公式仍可重算
- [ ] 真实 Excel 另存后仍能打开（无"需要修复"提示）

## B7 · 隐藏行列的截图与高度

**为什么测**：截图尺寸计算里"隐藏行列占 0 像素"这条规则是代码推断的，
**从未实测**——猜错就会出现图里留白或内容被截。

**前置**：空目录。

```powershell
mkdir D:\sjs-e2e\t7-hidden; cd D:\sjs-e2e\t7-hidden
```

**提示词**

> 新建一个工作簿：A1:C1 表头 序号/名称/金额，录入 20 行数据。
> 然后把**第 3 到第 8 行隐藏**，并把 **B 列隐藏**。然后：
> ① 截图 `hidden.png`（png 格式）
> ② 报告截图的实际像素尺寸
> ③ 报告：可见行有几行、被你隐藏的有几行、隐藏行读出来的行高是多少
> ④ 用这些数值算一下"截图高度应该等于多少"，和 ② 实测值对比，说明是否吻合
>
> 请用数值核对，不要只凭看图下结论。

**通过标准**
- [ ] 隐藏的 6 行 **不占** 截图高度（高度 ≈ 可见 14 行 × 行高 + 列头高 + 8）
- [ ] 隐藏列 B 不占宽度
- [ ] 模型给出了"预期值 vs 实测值"的对比，而不是只描述图片
- [ ] 若两者不符，模型如实报告差异

**核对**（人工看图时）

```powershell
Get-Item .\hidden.png | Select-Object Length
# 图片应能看到 1,2,9..20 行，且中间没有大块空白
```

## C6 · 超时之后同一会话能否继续

**为什么测**：已验证"超时不会写坏文件"，但没验证**超时之后队列/会话是否恢复正常**。
DSH 的默认超时是 **60 秒**，所以这条会真的等约 1 分钟。

**前置**：空目录。

```powershell
mkdir D:\sjs-e2e\t9-timeout; cd D:\sjs-e2e\t9-timeout
```

**提示词**

> 请严格按顺序做三步，每步做完再进入下一步：
>
> **第一步**：新建工作簿 `超时测试.ssjson`，写入 A1=`起点`，然后读回来确认。
> **第二步**：在这份工作簿上执行一段 `while(true){}` 死循环。我知道它会失败，
> 就是要看失败的样子——请把**完整的错误码和错误信息**原样贴给我，然后告诉我
> 这次调用花了大约多少秒。
> **第三步**：**在同一个工作簿上**继续写 A2=`超时之后`，读回来确认写入成功，
> 再导出成 `超时测试.xlsx`。
>
> 最后回答我一个问题：刚才那次超时，有没有把这份工作簿弄坏？

**通过标准**
- [ ] 第二步得到超时错误（预期 `SJS_WORKER_TIMEOUT`，约 60 秒）
- [ ] 第三步**成功**——超时没有卡死后续调用
- [ ] A1 的 `起点` 在超时后**仍然存在**（没被写坏/清空）
- [ ] 导出 xlsx 成功
- [ ] 模型明确回答了"有没有弄坏"

**核对**

```powershell
Get-ChildItem            # 应有 超时测试.ssjson / 超时测试.xlsx
```

## P1 · 大表性能与超时悬崖

**为什么测**：越界写入现在会自动扩容（不再丢数据），但**规模上去之后**耗时、
文件体积、导出/截图代价都是空白。单次操作预算是 **60 秒**，超过就
`SJS_WORKER_TIMEOUT`——需要知道悬崖在哪。

**已知基线**（本机实测，供对照）：写入 1 千行 ≈ 3.8s、5 千行 ≈ 4.1s、2 万行 ≈ 5.2s
（含约 3.5s 的 worker 冷启）；2 万行 ssjson ≈ 1.47 MB。

**前置**：空目录。

```powershell
mkdir D:\sjs-e2e\t10-perf; cd D:\sjs-e2e\t10-perf
```

**提示词（写入基准）**

> 做一次容量基准，逐档测：**1 万行、5 万行、10 万行**。每一档都：
> ① 新建工作簿 → ② 用 `sjs_execute` 写入（每行 3 列：序号、名称、金额，
> 金额用数字）→ ③ 在脚本里用 `Date.now()` 量出**写入耗时(ms)** →
> ④ 报告 `getRowCount()` 和 ssjson 文件字节数。
>
> 如果某一档**超时失败**，把错误码原样贴出来，说明是从哪一档开始的，并且
> **不要重试超过一次**。最后给我一张对比表。

**通过标准**
- [ ] 三档都有耗时/行数/体积（或明确标出超时）
- [ ] 没有静默丢数据（`getRowCount()` ≥ 目标行数）
- [ ] 若某档超时，如实报告且没有反复重试

**提示词（导出与截图代价）**

> 挑刚才**最大那档**的工作簿：
> ① 导出 xlsx，报告耗时和文件大小
> ② 截图 png，报告耗时、像素尺寸、以及 `clipped` 标志
> ③ `sjs_status` 报告 used range
> 如果截图因为太大被裁剪，明确说出来，别把裁剪图说成完整图。

**通过标准**
- [ ] 三项都有耗时数字
- [ ] `clipped: true` 被如实报告（大表必然超 2582×2182）
- [ ] xlsx 能被 Excel/WPS 打开

**提示词（往返校验）**

> 把刚才导出的 xlsx **重新导入**成新工作簿，报告导入耗时和得到的 used range；
> 然后抽查首行和末行的数据，确认与原始写入一致（给出具体值，别只说"一致"）。

**通过标准**
- [ ] 导入耗时 + used range
- [ ] 首/末行有具体值佐证，不是空口"一致"

**内存观测（可选，另开一个 PowerShell 窗口跑）**

worker 是短命子进程，用采样器抓它的峰值内存：

```powershell
$peak = 0
while ($true) {
  $m = (Get-Process node -ErrorAction SilentlyContinue |
        Measure-Object -Property WorkingSet64 -Maximum).Maximum
  if ($m -gt $peak) { $peak = $m; "{0,6:N0} MB" -f ($peak/1MB) }
  Start-Sleep -Milliseconds 300
}
```

跑上面任意一条提示词时开着它，记下最大值。
